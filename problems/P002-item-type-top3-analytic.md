# P002 — 2012년 3월 상품유형별 판매수량 상위 3개 상품

- 난이도: Lv3
- 주제: 분석함수(순위·비중) / 인라인 뷰 / 3테이블 조인
- 유형: 작성

## 요구사항
2012년 3월(`20120301`~`20120331`) 한 달간 팔린 수량을 **상품별로 합산**한 뒤,
**상품유형(ITEM_TYPE_CD)별로 판매수량이 많은 상위 3개 상품**만 뽑는다.
각 행에는 그 상품이 **자기 유형 전체 판매수량에서 차지하는 비중(%)** 도 함께 낸다.

- 순위는 `RANK` 기준(동일 수량이면 같은 순위, 다음 순위는 건너뜀)으로 매기고 3위 이내를 출력한다.
- 비중은 **그 유형의 전체 상품 합계**를 분모로 한다. 상위 3개만 더한 값이 분모가 아니다.
  (즉, 상위 3개로 걸러내기 *전에* 계산해야 한다)
- 비중은 `ROUND(..., 1)` — 소수점 1자리까지.

출력 컬럼: `TYPE_NM`, `ITEM_NM`, `QTY`, `RNK`, `QTY_PCT`  (이 순서, 별칭까지 이대로)
정렬: `ITEM_TYPE_CD` 오름차순 → `RNK` 오름차순 → `ITEM_NM` 오름차순
  ※ `ITEM_TYPE_CD` 는 **정렬에만 쓰고 출력하지 않는다**
결과 행 수: **18행**

## 참고 정보

**ORD_ITEM** — 주문상세, 37,096,485 건 / 6.5GB
| 컬럼 | 타입 | 설명 |
|---|---|---|
| ORD_NO | NUMBER | 주문번호 (복합 PK) |
| ITEM_ID | NUMBER | 상품ID (복합 PK) → ITEM.ITEM_ID |
| ORD_ITEM_QTY | NUMBER | 주문 수량 |
| ORD_DT | VARCHAR2(8) | 주문일자 `YYYYMMDD` — **DATE 아니라 문자열** |
| ORD_HMS | VARCHAR2(6) | 주문시각 `HH24MISS` |

인덱스: `ORD_ITEM_PK(ORD_NO, ITEM_ID)` UNIQUE, `ORD_ITEM_X01(ORD_DT, ORD_HMS)`
2012년 3월 구간은 약 1,550,000 건.

**ITEM** — 상품, 92 건
| 컬럼 | 타입 | 설명 |
|---|---|---|
| ITEM_ID | NUMBER | PK |
| ITEM_NM | VARCHAR2(100) | 상품명 |
| ITEM_TYPE_CD | VARCHAR2(6) | 상품유형코드 → COM_CD.UNI_CD |
| SALE_YN | VARCHAR2(1) | 판매여부 (이 문제에서는 필터하지 않는다) |

**COM_CD** — 공통코드, 7 건
| 컬럼 | 타입 | 설명 |
|---|---|---|
| UNI_CD | VARCHAR2(6) | PK |
| UNI_CD_NM | VARCHAR2(100) | 코드명 |
| CL_UNI_CD | VARCHAR2(6) | 상위코드 (자기참조) |

값:
```
100    상품유형코드   (CL_UNI_CD = 'M', 루트)
100100 버거      100101 세트      100102 치킨
100103 디저트    100104 아이스크림  100105 음료   (CL_UNI_CD = '100')
```
유형별 상품 수: 버거 18 / 세트 17 / 치킨 8 / 디저트 12 / 아이스크림 12 / 음료 25 = 92

조인:
- `ORD_ITEM.ITEM_ID = ITEM.ITEM_ID`
- `ITEM.ITEM_TYPE_CD = COM_CD.UNI_CD`

데이터 기간: `ORD_DT` 20120101 ~ 20131231

## 제약
- 오라클 전용 문법으로 작성한다 (**ANSI 조인 금지** — `FROM a, b WHERE a.k = b.k`)
- 유형명(`TYPE_NM`)은 `COM_CD` 에서 조인해서 가져온다. `DECODE` 로 하드코딩하지 않는다
- `ROWNUM` 으로 자르지 않는다. 유형별 3개이므로 **분석함수**로 순위를 매겨 거른다
- 출력 별칭은 위에 적힌 그대로 (`TYPE_NM`, `ITEM_NM`, `QTY`, `RNK`, `QTY_PCT`)
- 힌트(`/*+ ... */`)는 쓰지 않는다
- 성능 목표는 따로 없지만 참고로 기준 답안은 Buffers 약 43,000 이다.
  `ORD_ITEM` 전체를 풀스캔하면 이보다 훨씬 커진다

## 출력 예시
형식 확인용이다. **아래 값은 실제 정답 값이 아니다.**
```
TYPE_NM     ITEM_NM              QTY      RNK   QTY_PCT
----------- ----------------- ------- -------- ---------
버거        AAA버거             99999        1       9.9
버거        BBB버거             88888        2       8.8
...
음료        ZZZ음료             77777        3       7.7
```
- `QTY_PCT` 는 숫자다. `6` 과 `6.0` 처럼 화면 표기만 다른 것은 같은 값으로 본다
- 유형은 `100100`(버거) → `100105`(음료) 순으로 나온다
